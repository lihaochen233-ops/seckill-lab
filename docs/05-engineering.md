# 第五课：把正确的下单逻辑放进可运行服务

## 身份不从请求体相信

`auth.Signer` 对 `userID.expiry` 用 HMAC-SHA256 签名。HTTP 服务验证签名和过期时间后才取得 user ID；`crypto/hmac.Equal` 用于比较签名。

这是教学用令牌格式，不是 JWT，也不是完整登录系统。`cmd/token` 是开发者签发测试身份的入口。内存模式额外开放演示发令牌接口，因此强制监听回环 IP。MySQL 模式关闭该接口。

获取订单时的查询同时包含 `id` 和 `user_id`。别人访问返回 404，避免泄露订单是否存在。仅猜不到订单 ID 不是授权机制。

## 并发数和速率不是同一个限制

`httpapi.API.slots` 是有缓冲 channel。写入一个空结构体表示拿到一个下单执行名额，函数结束取出释放。非阻塞 select 拿不到名额立即返回 429，防止下单操作无限堆积。它只限制下单关键处理，不是整个 HTTP 服务器连接数的硬上限。

Redis Lua 用 INCR + PEXPIRE 维护一秒窗口内尝试次数。多个实例用相同 Redis key 才能共享限制；部署多套互不相关的业务时应配置不同 key 命名空间。固定窗口边界存在突发，不能宣传成精准匀速控制。

为什么 Lua？把计数与首次设置过期一起执行，避免应用在两条命令之间崩溃而留下不过期的计数器。脚本的原子性也**不等于 Redis 与 MySQL 之间有共同事务**。我们只让 Redis 管限流，库存仍全部在 MySQL。[Redis 官方 INCR 限流模式](https://redis.io/docs/latest/commands/incr/)

## 超时、连接池、退出

HTTP 请求 context 给数据库查询和 Redis 操作一个三秒预算；网络读写也设置超时。取消 context 是协作式取消，不能保证任意函数会被强行终止。

`sql.DB` 是连接池，不能为每次请求重新创建；`sql.Tx` 是一次事务，不能在不同请求之间共享。连接池最大 20 条连接是教学默认值，不是通用最优参数。高并发等待会消耗请求预算，需要结合锁竞争与数据库容量调整。

收到 Ctrl+C/SIGTERM 后，`http.Server.Shutdown` 停止接受新请求，等待正在处理的请求完成，最多十秒。之后才退出并关闭数据库和 Redis 连接。Windows 下直接强杀进程不等于优雅退出。

## 指标含义

`/metrics` 暴露 created、replayed、rejected、failed 四类下单响应计数。rejected 包含认证、参数、业务拒绝和限流；failed 表示无法正常完成的基础设施错误。进程重启会清零，数据库订单才是持久事实，不能用指标直接对账。

`/healthz` 只证明程序能响应；`/readyz` 还检查数据库和启用的 Redis。真实部署时对指标与内部诊断端点做网络访问控制，配合 HTTPS 和账户系统。

本课练习：先把 `MAX_INFLIGHT` 调小观察 429，再让 Redis 不可用观察 503，检查库存没有无故减少。随后解释为什么调整限流不能修复有缺陷的库存事务。
