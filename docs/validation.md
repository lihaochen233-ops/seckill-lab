# 本机验证记录

日期：2026-09-25。Windows amd64，Go 1.26.5。使用安装在本机的 MySQL 9.7.0 程序创建独立临时实例，端口 13317；没有连接或修改用户原有 MySQL 实例的数据。

## 已执行

- `go test -count=1 ./...`：通过。
- 配置专用 `TEST_MYSQL_DSN` 后 `go test -count=1 -v ./internal/store`：真实 MySQL 契约、事务回滚、双连接池、跨商品同 key 冲突测试通过。
- `go test -count=1 -cover ./...`（包含真实 MySQL）：通过。关键包语句覆盖率 auth 95.2%、config 84.4%、httpapi 73.0%、store 71.3%；这不是端到端覆盖率，也不是质量的完整度量。
- `go vet ./...`、`go build ./cmd/...`：通过。
- Redis Lua 的并发上限、TTL 恢复、故障传播：使用 miniredis 测试通过。
- `cmd/migrate` 在独立库运行成功；卖完商品后再执行，库存仍为 0、订单数仍为 100，未重置。
- 浏览器内存模式：首次下单 201，再次点击同 key 返回 200、`replayed=true`、相同订单号，库存只减少一件。

## HTTP 实验

命令：`go run ./cmd/loadtest -url http://127.0.0.1:端口 -n 500 -c 32 -repeat 2`。两个模式都关闭 Redis，全新活动 100 件，每用户请求两次同 key，客户端和服务器在同一台机器。

| 项目 | 内存模式 | MySQL 模式 |
|---|---:|---:|
| 用户数 / HTTP 并发 | 500 / 32 | 500 / 32 |
| 总请求 | 1000 | 1000 |
| 新建订单 201 | 100 | 100 |
| 幂等重放 200 | 100 | 100 |
| 售罄 409 | 800 | 800 |
| 最终库存 | 0 | 0 |
| 独立订单数 | 100 | 100 |
| 异常响应 | 0 | 0 |
| 客户端 P50 | 0.513 ms | 15.239 ms |
| 客户端 P95 | 1.561 ms | 89.976 ms |
| 整批下单请求耗时 | 约 19 ms | 约 905 ms |

MySQL 模式额外 SQL 核对 `initial_stock=100, stock=0, COUNT(orders)=100`。压测工具检查所有成功订单可以由对应用户查询。

**这些数字只是一次短时本机实验。** 大部分响应是售罄/重放；不能据此宣称持续的数据库写单吞吐，更不能将内存请求速率写为线上 QPS。令牌准备、前后库存读取和最终订单查询不在批量请求计时内。CPU、其他进程、磁盘和缓存状态会影响重复结果。

- 未连接真实 Redis 服务；miniredis 不代替真实部署、持久化、主从或故障切换验证。
- 没有长时间容量测试、跨主机压测或生产运行数据。

排障附记：本机 MySQL 9.7.0 在带中文的临时数据目录初始化成功但启动失败，改为系统临时目录下的 ASCII 路径后正常；因此正式数据库建议使用已有可靠配置，测试数据目录使用 ASCII 路径。本机发现并修复过跨列 CHECK 必须写在表级的 SQL 问题，已通过真实建表验证。

收尾记录：独立 MySQL 测试实例已通过 mysqladmin 正常关闭。自动审批以“策略阻止”拒绝了临时数据目录的递归删除，未给出更具体原因，因此保留 `.local/mysql-data` 和 `.local/mysql-test-path.txt` 所记录的系统临时目录；两者均为本次创建的测试数据，不是项目运行依赖，也不应加入版本库。演示服务单独运行于 `127.0.0.1:18080`，库存已恢复为初始状态。
