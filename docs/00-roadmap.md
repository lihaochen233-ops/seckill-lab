# 按重要性安排学习，而不是按文件夹顺序背代码

目标：面试时能从一次 HTTP 请求讲到数据库提交，并能用实验支撑“不会多卖、不会多扣”。建议每天 1～2 小时，下面天数只是参考，通过验收再前进。

| 阶段 | 优先级/参考时间 | 读哪些文件（相对项目根目录） | 验收标准 |
|---|---|---|---|
| 1. 请求主线 | P0 / 1～2 天 | `cmd/server/main.go`、`internal/domain/model.go`、`internal/service/service.go`、`internal/httpapi/api.go` 中的 `buy` | 能画出 HTTP → 业务 → 存储 → 响应，跑通页面 |
| 2. 超卖与原子性 | P0 / 2 天 | `cmd/oversell/main.go`、`internal/store/memory.go` 的 `Buy` | 能解释库存 0 为什么仍然超卖；知道锁必须覆盖完整临界区 |
| 3. MySQL 防超卖 | P0 / 3～4 天 | `migrations/001_init.sql`、`internal/store/mysql.go` 的 `Buy/buyTx` | 能说明行锁、事务、条件更新各自作用，自己写出核心 SQL |
| 4. 幂等与验证 | P0 / 2～3 天 | `contract_test.go`、`api_test.go`、`cmd/loadtest/main.go` | 解释超卖、重复购买、幂等的区别；运行并理解并发/回滚测试 |
| 5. 工程能力 | P1 / 2～3 天 | `auth/token.go`、`limit/redis.go`、`httpapi/api.go`、`config/config.go` | 能解释 401/403或404/409/429/503、超时、连接池与优雅退出 |
| 6. 项目表达 | P1 / 1 天 | `docs/06-resume.md`、自己的实验记录 | 讲清实际实现、取舍、瓶颈，简历没有虚构指标 |
| 7. 扩展 | P2 / 按需 | `docs/07-next-steps.md` | 自己完成一个新需求并补充关键场景测试 |

学习方法：先预测结果，再运行；先讲出“为什么需要这一行”，再去记语法。你不需要第一天就读完 SQL、Lua 和令牌算法。

每节提问都可以采用下面格式：

> 我在第 3 阶段，看 `internal/store/mysql.go` 的 `buyTx`。我理解 `defer tx.Rollback()` 是失败时撤销操作，但为什么提交成功后还要调用它？请按执行顺序举例。

我们后续按“你目前的理解 → 具体运行过程 → 小实验 → 你自己复述”逐一讲。不会一次把所有中间件塞给你。

完成记录（由你自己打勾）：

- [ ] 我运行过一次成功抢购和同 key 重试。
- [ ] 我能不用代码解释超卖的发生过程。
- [ ] 我能不看答案写出事务内扣库存和订单插入。
- [ ] 我能说清唯一约束和幂等 key 为什么缺一不可。
- [ ] 我跑过真实 MySQL 测试，而不只是内存测试。
- [ ] 我能用自己的语言讲一次失败处理和一个性能取舍。
- [ ] 我独立修改过一个需求，能够解释自己的改动。
