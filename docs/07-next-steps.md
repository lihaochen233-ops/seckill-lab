# 第七课：做自己的扩展

以下是未来练习，**当前未实现**。按顺序做，每次完成一个闭环。

1. **新增活动命令与分页查询**：补正数库存/整数金额/时间区间校验；通过后台命令创建新活动，避免直接重置已经成交的库存。分页要有稳定排序和上限。
2. **完善可观测性**：记录请求 ID、延迟、业务错误码；区分数据库锁等待和应用排队；日志不记录令牌和密码。先提出要回答的问题，再加指标。
3. **订单取消与库存归还**：先设计状态转移，再实现事务内“仅从可取消状态转为取消并加回库存”。重复取消不能重复加库存；决定取消后是否允许再次抢购，再调整唯一约束，不要直接删掉订单。
4. **过期释放库存**：在上一步稳定后再加定时扫描。多个 worker 竞争同一订单要只有一个释放成功；不能只用进程内 timer，重启会丢任务。
5. **Redis 预扣与 MQ 异步下单**：前四阶段熟练后才尝试。提交接口返回“已受理”而非“已下单”，另提供结果查询。设计 outbox 或可靠事件投递、消费幂等、失败重试、死信、预扣补偿、进程崩溃恢复和 Redis 数据重建。Lua 只保证 Redis 内部操作原子，不会把消息队列与 MySQL 自动变成同一事务。

每次升级都先写故障清单：在每一步后杀进程、网络超时、重复执行，会发生什么？能否恢复？是否多扣或多还库存？可以合理缩小范围，但应明确边界并验证。
